# Server context

- Consult the current [design documentation](../wiki/Design-Documentation.md) and [requirements and specifications](../wiki/Requirements-and-Specifications.md) before server changes. Recheck relevant requirements instead of treating this file or an earlier iteration's scope as a fixed specification.
- Work from `server/` with uv and the Python version declared in `pyproject.toml`. `uv sync --locked` installs the locked environment. Run `uv run ruff check .`, `uv run ruff format --check .`, and `uv run pytest` after code changes. `ruff.toml` is copied from the root.
- Start with `uv run uvicorn pix_server.main:app --host 0.0.0.0 --port 8000 --workers 1 --ws-max-size 65536`. Without `PIX_REDIS_URL` the rooms stay inside the process (fakeredis, a development dependency), so run one worker; with it, any number of workers share the rooms. The deployed image has no fakeredis and refuses to start without `PIX_REDIS_URL`.
- The server is hosted on two course servers that are reachable only through the course's HTTP proxy on port 80: no TLS, no other inbound port, and no SSH from GitHub. Design 2.8 (Hosting, Deployment) records the proxy's measured behavior and the deploy flow; do not assume `https://`, `wss://`, or a TURN relay on the host.
- Deployment lives in `Dockerfile` (pytest is the `test` build stage; `runtime` is what runs) and `deploy/`: `docker-compose.yml` (nginx plus two copies of the app, `app-blue` and `app-green`), `nginx/nginx.conf`, and `deploy.sh`, which a root systemd timer runs every minute on each server. The README's Deploy section has the flow and the commands. nginx forwards only `/api/v1/`, `/ws`, and `/health`, so a new public route must be added to `nginx.conf`; keep `/internal/*` out of it, because `deploy.sh` reads `/internal/stats` inside the container to wait for open rooms before it switches copies. That wait stays until the app can rejoin a room after its socket drops (#56): the two copies share rooms through the Compose file's `redis` service, but stopping a copy still closes its sockets. Keep `deploy.sh` runnable by bash 3.2, so it can be tried on macOS with `PIX_HOME` pointing at a scratch directory, and keep all of it inside functions, because a deploy checks out another version of the file while it runs. The `server-image` workflow builds the image and checks the routes through nginx; `server-deploy` only waits for `/version`.
- Keep the server's signaling protocol aligned with Android's [SignalMessage.kt](../android/app/src/main/java/com/lastpenguin/pix/session/signaling/SignalMessage.kt) and the current design documentation. When the protocol changes, update the affected implementations, tests, and documentation together.
- Room state lives in Redis (`store/`, Design 2.7, AD-18), and `SessionRegistry` keeps only this process's sockets. Every room transition is one Lua script in `store/scripts.py`: change state there, never with several Redis calls from Python, or two workers can interleave. A script returns the messages to deliver as rows and Python builds the JSON; do not use `cjson` or `unpack` in a script, because fakeredis lacks them. A script gets the time from its caller, so tests keep the fake `clock`; only the worker heartbeat uses a real Redis expiry. Each socket has one writer and a bounded queue so slow clients cannot block other rooms.
- See [README.md](README.md) for the implemented scope, lifecycle behavior, and configuration, and [config.py](src/pix_server/config.py) for current defaults. Keep those details aligned with evolving requirements rather than duplicating iteration-specific rules here.
- Pose generation lives in `poses/` and calls the same OpenRouter Image API as the comparison script below. It sends one fixed payload to every model, relying on OpenRouter ignoring fields a model does not support, so `PIX_POSE_MODEL` (`id` or `id@quality`) changes the model without code changes; the seed is folded below 2³¹ because Seedream rejects larger values. Keep the REST contract aligned with Android's [PixApi.kt](../android/app/src/main/java/com/lastpenguin/pix/core/network/PixApi.kt) and [ApiModels.kt](../android/app/src/main/java/com/lastpenguin/pix/core/network/ApiModels.kt) and the current design documentation. Every REST error goes through `ApiError` in `errors.py`; request-validation failures answer `400 INVALID_REQUEST` because 422 means `REJECTED`. `OPENROUTER_API_KEY` is read without the `PIX_` prefix. Never log or store scene photos, candidates, or any part of an upstream response body, which can quote the input; log only the upstream status. The rate limit is a script in the session store, shared by all workers; a request that cannot be counted because Redis is down answers `503 UNAVAILABLE`. `RequestBodyLimitMiddleware` refuses requests over `MAX_REQUEST_BYTES` before they are parsed; keep that at or below Starlette's spool threshold (`MultiPartParser.spool_max_size`), or uploads are written to temporary files. `POST /poses` polls `request.is_disconnected()` and cancels the upstream call when the phone drops the request, which OpenRouter then does not bill; this needs a real connection, so its test runs a real Uvicorn server instead of the test client. The README's Deploy section records how nginx and the course's proxy treat this and the per-address rate limit.
- A cancelled task that is inside a Redis call can surface as a `RedisError` instead of `CancelledError`, so background loops in the registry stop on a flag as well, and a socket handler frees its place in the store from a task of its own (`SessionRegistry.disconnect`). In the handler's cleanup wait for child tasks with `asyncio.wait`, not `gather`: under the test client's cancel scope `gather` can raise a `CancelledError` without a message, which fails the test at socket exit, mostly on Linux. Tests use fakeredis by default and a real Redis when `PIX_TEST_REDIS_URL` is set; CI runs both, and the image build's test stage has only fakeredis.
- Tests must never reach OpenRouter: the `client` fixture injects the fake `image_api` transport, and the `settings` fixture pins the key and model so a developer's environment cannot leak in.
- `scripts/` holds helper scripts that do not import `pix_server`. They use the server's locked dependencies, run with `uv run scripts/<name>.py`, and are checked by Ruff. `compare_image_edit_apis.py` benchmarks image-editing models through OpenRouter's dedicated Image API (`POST /api/v1/images` with `input_references`, not chat completions; per-model parameters come from `GET /api/v1/images/models`) and writes scene photos and results to the git-ignored `scripts/out/`.
- Server CI has separate workflows in `../.github/workflows/` reporting `server-lint` (Ruff lint and formatting), `server-test` (pytest), and `server-image` (the Docker build and the nginx routes); these names are intended for required status checks. Coordinate renames with branch rulesets, and avoid workflow-level PR path filters that could leave required checks pending.
