# Android context

- CameraX is the sole camera owner. Bind it to the Camera screen's view lifecycle, not the activity. Preview, capture, and analysis share a portrait 3:4 viewport; PreviewView uses FIT_CENTER so it shows that entire crop. Saved photos never include View overlays.
- CameraController.status is a local contract extension for asynchronous startup/failure handling. READY requires an open camera and an analysis frame. Include this extension in contract review and the wiki design update when preparing its PR.
- Call grabFrame before navigation stops the camera: it snapshots cached YUV data before suspending, then converts the caller-owned image off the main thread. FrameSink runs on the serial analysis executor and must copy/crop/rotate as needed and close ImageProxy before returning; never retain camera buffers or wait on the network.
- Camera's ratio readout renders observed zoom; remote zoom must echo that same applied state. While a zoom slider is being dragged, asynchronous observations must not move its thumb away from the user's target. Subject view shows the requested ratio optimistically during its drag and settles on the applied echo afterward. Camera status is separate from whether the preview surface has displayed a frame; use camera.preview timing for visible startup.
- All camera ratios use primary-rear-camera units, including capabilities and remote echo. Prefer native logical-camera zoom; a separately exposed ultrawide is eligible only if its normalized range overlaps the primary range. Preserve the real hardware minimum, continue an existing slider drag through STARTING during lens switching, and defer lens changes until an in-flight capture finishes.
- Camera and Subject view each use a single-value Material zoom slider with actual minimum/maximum labels, native keyboard/accessibility support, and the ratio readout's Zoom in / Zoom out actions. SubjectViewModel.onZoomGesture remains the remote API: drag steps are throttled to 50 ms and release, cancellation, or pause finishes with one reliable final value; discrete keyboard/accessibility changes are final requests. CameraCapabilities.zoomStops remains in the contract for later controls. Neither preview nor subject video interprets pinches as camera zoom. Use `TrackedSliderController` for every Material slider (camera zoom, remote zoom, guide opacity): it keeps the thumb under the user during a drag and commits exactly one final value.
- Guide drag and pinch stay on the editable overlay. A touch starting inside the visible guide bounds belongs to guide editing until all fingers lift; one starting outside does not edit the guide or zoom the camera. Keep splitMotionEvents disabled on the preview container to preserve a single guide touch sequence as fingers join or leave. Read-only guide overlays pass touches through.
- CameraCompositionView draws only inside the fit-centered 3:4 image; it is non-clickable so camera/guide gestures pass through. Its view-scoped CameraLevelMonitor starts on resume and stops on pause, with gravity/accelerometer fallback and no shared camera or session state. Grid and level aids never enter ImageCapture or ImageAnalysis.
- Run ./gradlew spotlessCheck :app:lintDebug :app:testDebugUnitTest :app:assembleDebug from android/. All tests live in `app/src/test/` (no `androidTest`): pure logic uses plain JVM tests, and View/Canvas/touch/Material tests use Robolectric via `AndroidJUnit4` with native graphics. Robolectric's SDK 36 sandbox needs JDK 21+; Android Studio's JBR works. Permissions, real CameraX capture, MediaStore, and hardware resolution still require an emulator or phone.
- The UI is the dark-only `Theme.Pix`: build screens from the tokens in `res/values/colors.xml` and the `TextAppearance.Pix.*` / `Widget.Pix.*` styles in `styles.xml`, not raw colors or Material defaults ([README.md](README.md), Look). Each text appearance names its font weight's file; never set `android:fontFamily` in the theme, because a theme-level value overrides every text appearance's font. Two-way switches such as Cutout / Outline are `Widget.Pix.Button.Segment` buttons selected with `View.isSelected`.
- To render screens in a Robolectric test, inflate through a started `AppCompatActivity` (`Robolectric.buildActivity(...).setup()`) and attach the view to its window. Otherwise `<Button>` stays a platform Button, `app:` attributes are ignored, and start drawables and button icons are not laid out.
- Open `android/` in Android Studio. Commands for formatting, lint, unit tests, and the build are in [README.md](README.md); run them from `android/` before pushing. If `java` is not on the PATH, set `JAVA_HOME` to Android Studio's bundled JBR.
- The shared contracts listed in [README.md](README.md) change only through a reviewed pull request together with the Design Documentation. Module classes behind them belong to the issue owner named in each file's `Owner:` comment; keep other owners' `TODO(#n)` markers in place.
- `core/AppContainer.kt` is the only place modules are created, and `ui/PixViewModels.kt` the only place ViewModels get them. Replace a module with a fake there, never in a screen.
- `BuildConfig.SERVER_URL` comes from `pix.serverUrl` in `local.properties` or a Gradle property and defaults to the emulator's host address; only debug builds allow plain `http://` and `ws://` (`src/debug/AndroidManifest.xml`).
- Session code (`session/`) touches its state only on `RtcSessionManager`'s serial scope; WebRTC and OkHttp callbacks only publish events. Never call `dispose()` from a WebRTC callback thread, and dispose the peer connection before the video source; it disposes the tracks itself.
- Screens render from `SessionViewModel.state` and navigate from `SessionViewModel.transitions` (one-shot). After the subject leaves, the photographer is back in `Waiting(code)`, not `Ended`; the subject gets `Ended(CONNECTION_LOST)` and reconnects with the same code.
- The camera binds to the Camera screen's view lifecycle and streams frames through `CameraController.setFrameSink` from `Connecting` on; leaving the screen pauses the subject's video, and 60 s of the whole app in the background ends a live session (`ProcessLifecycleOwner` in `SessionViewModel`).
- Guide sync (`session/GuideSyncer.kt`): the photographer sends while `Connected`; the subject receives from `Connecting` on, because `SessionManager.incoming` does not replay and the image can arrive before the subject's own `Connected`. The subject's `hello` carries the mirror's guide id so an image it already has is not resent. The guide image is the cutout only (WebP with alpha, ≤ 720 px tall); the subject rebuilds the outline with `OutlineExtractor`. Bitmap work stays behind `GuideImageCodec` so syncer tests run on the plain JVM.
- Pose generation prepares the scene photo on the phone (`AndroidPoseImageCodec`: long side at most 1024 px, JPEG 85, no EXIF); the server rejects anything else and never resizes. The scene photo is a step of the Camera screen, not a screen of its own: while `GenerationUiState.phase` is `FRAMING` or `REVIEWING`, `CameraFragment.renderScenePhoto` runs last in `render` and overrides the camera's own controls, and the shutter calls `GenerationViewModel.takeScene` (`grabFrame`) instead of saving; nothing is sent before *Use this photo*. The pose API's OkHttp client must wait longer than `RemotePoseGenerator.TIMEOUT_MS`; OkHttp's 10 s read timeout would end every generation. The generation screens navigate from `GenerationUiState.phase` and only while they are the current destination. `RemotePoseGenerator` takes its image codec and dispatcher as parameters so its tests run on the JVM.
- To drive the app on an emulator from the shell, `adb shell uiautomator dump --windows` is needed to see bottom sheets and dialogs; the plain dump often returns only the activity's window.
- JVM unit tests use `isReturnDefaultValues`, so `Log` and `SystemClock` are safe to call, but framework objects such as `Uri.parse(...)` come back null; a test that needs a real `Uri` runs under Robolectric. A session test that ends while connected must call `leave`, because the 2 s ping loop never lets `runTest` drain virtual time.
